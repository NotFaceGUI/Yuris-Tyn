# 05 · 1:1 对齐总纲（超集边界 · 功能矩阵 · 验收）

> 本文是渲染子系统的**对齐契约**。原则一句话：
> **SDK 渲染框架的每一项可观察行为都必须被支持；允许超集（扩展/性能/实现差异），不允许"不支持"。**
> 依据 = `01`–`04` 的二进制证据；状态 = 对照 `PROGRESS.md` 成果 113/121/122 与 `crates/yuris-render` 现状（2026-10-15）。

## 1. 对齐规则（超集的边界）

1. **行为集合对齐**：凡原引擎在屏幕上可产生的效果（含错误表现的 fallback），本仓库要么逐像素等价，要么显式报 `Unimplemented`（strict 下挂起、lenient 下按引擎风格跳层继续——见 01 §5）。**禁止静默近似**：近似只能作为过渡实现并登记矩阵编号。
2. **实现自由**：wgpu 不必复刻 D3D9 调用序列/固定管线形态；可以合并 pass、GPU 化 CPU 顶点运算、缓存 pipeline。判据只有 §4 的对拍，不是 API 形状。
3. **性能扩展允许**：分层缓存（组纹理不重画）、纹理图集、多线程命令录制等均可——前提是不改变单帧可见结果与命令侧可观察时序（挂起/推进语义归 VM，不属于本文）。
4. **数值口径**：`A` 内部存 0..256；固定管线等价路径 `min(A,255)/255`，着色器等价路径 `A/256`（04 §1）。中间精度与取整以对拍裁定，不预设。
5. **未裁定的模式不进核心路径**（铁律 2/3）：矩阵里 `Unknown` 的项，实现侧保持 `Unimplemented`，并保持本文件的挂号同步。

## 4. 验收（怎么算"1:1"）

1. **对拍源**：SDK ERIS 样例（`target/sdk/0.495/…/システム/data/`，800×600，官方素材、无版权风险）
   用原 `yu-ris.exe` 跑 → 逐场景截屏基准；同素材构造 ERIS 源用本内核跑 → 同机位截屏。
   商业样本（<game-b> / <game-a>）仅作补充对照，产物不入库。
2. **像素判据**：纯色/合成场景逐像素比较（允许 ±1 量化差，源自未知取整序的先挂"取整序"号）；
   渐变/过渡场景按帧序列比较（同 T 步进同输出）。
3. **判定程序**：`cargo run -p yuris-tools --example …`（新增 `shotcmp`）输出差异率；
   每关闭一个 R 项在 `PROGRESS.md` 记成果（含基准图 hash、差异率、命令）。
4. **回归**：现有 165+ 测试全绿为门槛；渲染新增单元测试按"公式表驱动"（03 §2 的状态序列 → 期望混合式）编写。
