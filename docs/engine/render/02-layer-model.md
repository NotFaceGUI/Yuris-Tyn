# 02 · 图层模型（结构 / 图层组 / 属性语义）

> 目标 `yu-ris.exe` sha256 `4f5eefa3…`。"层+0xNN"指图层结构体（CG 命令的持久对象）内偏移。
> 等级标注：表内偏移全部来自反编译实测（**Confirmed**）；"参数名 → 槽位"的绑定除注明外 **Likely**（写侧绑定见 §5 挂号）。

## 1. 图层结构体偏移表（绘制侧读到的全部字段）

| 偏移 | 类型 | 语义 | 证据 |
|---|---|---|---|
| `+0x34` | ptr | （节点内）指向图层本体 | 遍历器 `node+0x34` |
| `+0x4c` | u8 | 帧推进标志 A（非零 → 每帧调 `FUN_004141e4`） | 遍历器 |
| `+0x78/+0x7c` | i32 | 宽 / 高（`YS_PASTESPRITE` 用） | `decomp/0040ae99` |
| `+0x80` | i16 | **`A` 不透明度（存储 0..256）**；绘制入口 clamp 0..255 供固定管线，HLSL 用 `A×1/256` | 绘制函数 + `YS_AlphaVal` SetFloat；写侧见 04 §1 |
| `+0x82` | i16 | 过渡进度 `T`（Likely；与 `+0x84` 一起进 FadeVal 公式，见 04 §2） | 绘制函数 HLSL 通道 |
| `+0x84` | i16 | 过渡精度 `TA`（Likely）；`<1` 时判定"无过渡"，直接走 `BeginPass0` 之外的分支 | 绘制函数 `BeginPass` 门控 |
| `+0x86` | u8 | 属性字节（FILE 替换时随 `+0x87` 一起复制/交换；具体语义 Unknown） | `decomp/0042f809`、`0042f57d` |
| `+0x87` | u8 | **`MODE` 描画模式 0..18** —— 写侧 `CG[MODE=…]` 处理体 `0x42b028..0x42b053`（上游 render-semantics §2b 实测），消费点 = 绘制函数分派 | Confirmed（两侧都实证） |
| `+0x89` | u8 | 层有效标志（0 → 遍历器直接跳过）；层属性交换时参与交换 | 遍历器 + `0042f57d` |
| `+0xa4` | u8 | 层类：**0=无效（E=0，不进绘制）/ 1=正常 / 2=调试专用层** | 遍历器 + 绘制函数调试分支 |
| `+0xa6` | u8 | 部件计数 A（0 或 `+0x84<1` 时走无 HLSL pass 的简化路径） | 绘制函数 |
| `+0xa7` | u8 | 部件计数 B（非零 → 多部件外循环） | 绘制函数 |
| `+0xb0` | i32[] | 部件表 1（内循环逐项读，参与顶点几何） | 绘制函数内循环 |
| `+0x130` | i32[] | 部件表 2（同上） | 绘制函数内循环 |
| `+0x1b0/+0x1b8/+0x1c0/+0x1c8` | i64 | 百分比参数 ×4（绘制时 `÷100.0`；对应 CG 的 X/Y/中心/缩放族，逐槽绑定 Likely） | 绘制函数开头 |
| `+0x1d0/+0x1d8` | i64 | 百分比参数 ×2（`÷100.0`） | 同上 |
| `+0x1e8` | i64 | 过渡进度（遍历器调试分支按 `0.5×值/100` 消费） | 遍历器 |
| `+0x1f8/+0x1fc/+0x200` | f32 | 百分比参数 ×3（`÷100.0`；进旋转矩阵 `×π/180`，对应 FRX/FRY/FRZ 族，Likely） | 绘制函数 + 常量 0x58ebf8(π/180) |
| `+0x208` | ptr | 名称/E-mote 资源指针（调试分支 `"ieFE.exe"` 比较为反编译伪差，实为指针使用） | 遍历器 |
| `+0x210` | u8 | 帧推进标志 B（非零 → `FUN_004141e4`） | 遍历器 |
| `+0x21c` | ptr | **本层纹理 `IDirect3DTexture9*`**（判空 = 整层不画） | 绘制函数入口 + `SetTexture(0, …)` |
| `+0x61c` | ptr | 调试/组用的离屏渲染目标 | 遍历器调试分支 |

> 部件模型：`+0xa6/+0xa7` 计数 + `+0xb0/+0x130` 两张 int 表 = **一"层"可含多个部件四边形**
>（内循环逐部件 `SetTexture(0, 层基址+步进+0x21c)`），即"基图+部件"（立绘差分）在引擎层原生存在
> —— 与成果 85 的"基图+部件"模型互证。本仓库 Scene 的"一层一纹理"要超集化为一层多部件才能 1:1。

## 2. 图层树与图层组（`ID` 尾 `/`）

- 场景 = 节点链表（`node+0xc` → next），遍历器递归 `node+0x30` 有子节点的组。
  **绘制顺序 = 链表顺序**；`Z` 只影响入链位置。
- 组 = 先把子层画进组自己的离屏目标（`+0x61c` RT，合成纹理落在 `+0x90`），
  再把组当普通层画 ⇒ **组的 `A`/`MODE` 作用于"子层合成后的位图"**（手册原文的二进制机制，Confirmed）。
  离屏目标由 `FUN_0x462e40` 族创建（`CreateTexture(W,H,1,Usage=RENDERTARGET,…)`，上游 render-semantics §2b 实测，本次复核成立）。
- `E=0`（`+0xa4==0`）对组同样生效：整组不进绘制函数。
- **对齐要求**：本仓库 `Scene` 需要引入"组层 = 离屏 pass"的分层合成（wgpu render-to-texture），
  组属性（`A/MODE/E/SX/SY`）作用于合成结果，不得把组属性下推到子层。

## 3. 属性生命周期（创建 / 替换 / 交换）

- **FILE 替换保留属性**（手册规则实证）：`FUN_0042f809` 替换 `+0x90` 纹理时，
  把 `+0x80(A) +0x82(T) +0x84(TA) +0x86 +0x87(MODE) +0x1e8(过渡)` 从旧纹理对象整体搬到新对象
  —— 重复 `CG[FILE=…]` 只换图、不重置属性，**Confirmed**（反编译 `decomp/0042f809`）。
- **层属性交换**：`FUN_0042f57d` 交换两层的 `+0x89 +0x80 +0x82 +0x84 +0x87`（Confirmed）。
  对应脚本命令（`CGACT[SWAP]` 族）的命令名绑定 Unknown（命令层对齐时再定）。
- `FILE=""` = 1×1 黑图（手册，成果 113/122 已按手册实装），本次未再逆向图片装载路径
  （扩展名探测 `.PNG→.BMP→.JPG→.GIF` 维持手册等级 Confirmed(规范)）。

## 4. `Z` 与同序稳定

- 引擎对同 `Z` 按**链表序（创建序）**叠放（游戏不设 `Z` 时如此，成果 122 实机观察 + 本遍历器机制一致）。
- 对齐要求：本仓库排序键 = `(z, 创建序)`，稳定排序；不得引入"按路径推断 z"（已被成果 122 勘误）。
